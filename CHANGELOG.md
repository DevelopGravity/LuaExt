# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). What a major, minor or patch release is allowed to change is [the versioning policy in the README](README.md#versioning); the mechanics are that tags carry **no `v` prefix** (e.g. `1.0.0`, not `v1.0.0`), `composer.json` carries no version key, the git tag is the sole version record, and `PHP_LUAEXT_VERSION` in `php_luaext.h` must match it exactly.

## [Unreleased]

Nothing is released yet, so this section is a running record of what exists rather than a diff against a previous tag.

### Added

- **Vendored Lua 5.5.1**, patched. Every patch is guarded by `LUAEXT_LUA_HOOKS`, so compiling with it at `0` reproduces upstream byte for byte; `tools/vendor-lua.sh --check` verifies the tree against the pinned tarball plus the committed patch series.
- **Core execution**: `Sandbox` construction and teardown, `compile()`/`eval()`/`call()`, `LuaFunction` handles, dotted-path global access, and value conversion in both directions.
- **PHP callbacks**: `registerLibrary()`/`registerObject()`, including re-entrant Lua → PHP → Lua calls.
- **Object proxies**: `registerClass()` lets instances of host-registered classes cross into Lua as unforgeable userdata proxies — colon-dispatch instance methods, statics and `.new` on a class table, fluent chaining through auto-wrapped returns, `tostring()` via a marked `__toString()`, an equality chain that can never abort a script, and mapped operators (`<`, `<=`, `==`, arithmetic, unary minus, concatenation) validated at registration. `#[LuaClass]` carries a wrapper's configuration declaratively and `SandboxConfig::$classes` grants it at construction; trust stays per-sandbox and exposure stays explicit. Proxy lifetime rides the existing defer queue (destructors run at the boundary, never inside Lua's collector), sandbox↔object reference cycles are visible to PHP's cycle collector, and `SandboxStats::$liveObjectProxies` counts what the interpreter holds.
- **Runtime limits, actually enforced**: CPU, wall-clock, memory and output budgets. The interrupt check is compiled into the interpreter's own back edges rather than delivered through a debug hook, so it costs nothing on the dispatch path; a process-wide watchdog thread covers breaches while the owner is blocked outside the VM. `Sandbox::features()` reports the real per-platform enforcement level and clock resolution.
- **Capability-gated standard library**: an allow-list assembled member by member into a scratch table, never a scrubbed open state. Replacements for `print`, `pcall`/`xpcall`, `collectgarbage`, `math.randomseed` and `warn`; a filtered `debug` table; a hand-written `os` limited to time and environment. `tools/audit-stdlib.php` enforces the resulting surface against committed golden files.
- **Coroutines**, on by default and strictly call-scoped: every coroutine created during a call is force-closed when that call returns, so no suspended Lua state survives it. Capped by `maxLiveCoroutines` and `maxCoroutineDepth`, with a collection before the cap is enforced so the limit describes what is alive rather than what was ever created. The interrupt follows whichever coroutine is running, so work moved into one is still billed to the sandbox's CPU and memory budgets.
- **Fatal errors that user Lua cannot swallow**, covered by an adversarial suite spanning `pcall`, nested `pcall`, `xpcall`, `__gc` finalisers, `<close>` handlers, and — for both the CPU and the memory case — `resume`, `wrap`, nested `resume` and `resume` inside `xpcall`. The memory case is checked on the `lua_resume` status rather than the error value, because a refused allocation raises `LUA_ERRMEM` carrying Lua's own string instead of the extension's unforgeable marker.
- **`io` output half**: `io.write`, `io.stdout` and `io.stderr`, needing no capability because they touch no storage. Writing to `io.stderr` is what makes the output callback's `$isStderr` argument true; the sink flushes on a channel change so interleaved writes keep their order.
- **Virtual filesystem**: `io.open` with `:read`/`:write`/`:seek`/`:close`/`:flush`/`:lines`, plus `io.lines` and `os.remove`/`os.rename`, all behind the `vfs` capability and a host `FileSystem`. A backend implementing `RangedFileSystem` is streamed through `readRange`/`writeRange`; anything else is buffered whole-file, and a script cannot tell which it got. Every `VfsQuota` field is enforced, including the file count. Handles are call-scoped like coroutines: an unclosed file is flushed and closed when the call that opened it returns.
- **`require()`** behind its capability, resolving through `package.loaded`, a cycle guard, the two limits, `package.preload`, the filesystem along `modulePaths`, and finally a host `ModuleResolver`. `package` exposes only `loaded`, `preload` and a read-only `path` — no `cpath`, `searchers` or `loadlib`, because each of those exists to reach a shared object. A module that fails while loading is not cached, so a later `require()` retries rather than replaying the failure.
- **Sampling profiler**, off by default: `enableProfiler()`/`disableProfiler()`/`getProfile()`. Arming the count hook costs ~2.6x on dispatch-bound code, which is why the shipped hot path stays hook-free and this is opt-in. `enableProfiler()` returns `false` rather than displacing the count hook on a build where it is carrying the CPU limit.
- **`SandboxStats` reports measured figures**, including CPU and wall-clock time read off the watchdog and bytes moved through the filesystem. Those were hardcoded zeros behind a TODO.
- **`SandboxStats` times host crossings**: `phpWallClockSeconds`/`phpCpuSeconds` cover calls out to PHP (registered callables, the output callback, the module resolver) and `vfsWallClockSeconds`/`vfsCpuSeconds` cover filesystem backends. Measured whether or not `Limits::$billHostTime` or `VfsQuota::$billWallTime` charged the same interval to the script, so a host that leaves billing off still sees what its callbacks cost. Only the outermost crossing of a nested chain records, so nothing is counted twice.
- **Output sink** with buffer, callback and discard modes, billed against the memory limit.
- Project documentation: `README.md`, `SECURITY.md`, and `docs/` — configuration,
  cookbook, exceptions, the Lua-side API, migration, performance, platform support and
  the browser playground.
- CI across Linux and macOS (x64 and arm64, NTS and ZTS, debug and release), plus valgrind, sanitizer and lint jobs.
- **Lua language conformance suite** (`tests/10-lua/`): roughly 400 assertions over the language itself — arithmetic and the integer/float split, metatables, the pattern matcher, `string.pack`, the table and math libraries, `utf8`, coroutines, error semantics, `<close>`, and the replaced `io`/`os`. The rest of the suite proves the sandbox holds and that the expected stdlib *names* exist; this proves the patched interpreter still computes Lua's answers. It is platform-neutral by construction and is the first part of the suite Windows runs.
- **`make check` and `make dev`**: one command that runs every gate CI runs, and one that runs the build, the suite and the gates together. A gate that cannot run reports `SKIPPED` and exits non-zero, because a check that did not run is not a check that passed.
- **`CONTRIBUTING.md`**: how to build (including the debug PHP, which is the only build whose allocator reports leaks), what each gate catches, where a new test belongs, and the C conventions — chiefly that `lua_error()` longjmps, so a frame holding an allocation across anything that can raise leaks it.

### Changed

- **Registrations own their names, exactly once.** `registerLibrary()`, `registerObject()` and `registerClass()` claim their Lua global for the sandbox's lifetime, and a later registration wanting a claimed name — same registrar or another — is refused with a `ConfigurationError` instead of silently overwriting or merging. The old `registerLibrary()` incremental merge ("two calls build one namespace") is gone: batch a library into one call. The new `unregister()` releases a claim so a name can be swapped — the global is cleared, a class registration stops wrapping new instances, and proxies a script already holds keep working, because an object a script was given cannot be taken back. `setGlobal()` remains the deliberate free-form write and never consults the claims.
- **Touching a withheld feature now raises `FeatureNotGrantedError` naming the capability.** Wholly absent libraries (`coroutine`, `utf8`, `require`, `package`, `debug`) stay genuinely `nil` — `if coroutine then` keeps working — and the interpreter's own error path classifies the touch instead of reporting a bare "attempt to index a nil value". Withheld members of always-present libraries (`load`, `warn`, `string.dump`, the gated `os.*`, `io.*` and `debug.*`) become truthy gate stubs that raise the same error when called, which means member-level truthiness is no longer a feature probe. The error is fatal: policy is not discoverable by `pcall`. Unrelated nil errors keep upstream's message byte for byte.
- **Host time is no longer billed to the script by default.** `Limits::$billHostTime` (new, default `false`) pauses both timing clocks across every host crossing — registered callables, the output callback, a `ModuleResolver` — under the same nesting rules as `pauseTimers()`: Lua re-entered from a callback is still billed, and a callback that calls `resumeTimers()` opts back in. Set it `true` to restore the old behaviour, where a breach inside a callback is delivered the instant it returns. `VfsQuota::$billWallTime` keeps governing filesystem backends on its own.

- **`Sandbox`'s usage and limit surface is smaller.** Six getters — `getMemoryUsage()`, `getPeakMemoryUsage()`, `getCpuUsage()`, `getWallClockUsage()`, `getOutputLength()`, `isOutputTruncated()` — are **removed**; each was a `stats()` field under another name, and `stats(): SandboxStats` is now the one way to read usage. The three limit setters are **replaced by `setLimits(Limits)`**, with `limits(): Limits` to read them back: the old three reached three of the fourteen limits a `Limits` carries, and the other eleven were always changeable but had no door. `$sandbox->setLimits($sandbox->limits()->with(cpuSeconds: 2.0))` changes one field. This also ends an inconsistency where `cpuSeconds: 0.0` meant "no limit" through the constructor and was refused by the setter. See [docs/migrating-from-luasandbox.md](docs/migrating-from-luasandbox.md).

### Fixed

Nothing has been tagged, so none of these ever shipped — but each is recorded because each came with a regression test and, where the mistake was mechanically detectable, a new rule that refuses it.

- **A host callback re-entering Lua from inside a coroutine mixed up the two interpreter states.** `LuaFunction::call()` and `wrapCallable()` pushed onto the main thread while the consumer resolved against the running coroutine — with a zero-argument callback the resolved index left the stack entirely, calling whatever a stale slot held. Both halves of the boundary now name one state explicitly, and `luaext_exec_pcall()` refuses an index that resolves below the stack.
- **Describing an error ran script code under an unlimited memory ceiling.** The message handler lifted the ceiling so an out-of-memory report could not itself fail — but describing an error calls `tostring()` on it, and a script chooses what that does. From a default sandbox, `error(setmetatable({}, {__tostring = …}))` allocated past every budget and could kill the request; the result was also copied into an unbounded persistent string. The handler now grants a fixed 256 KiB headroom and keeps an 8 KiB prefix of script-supplied text.
- **Two stack-arithmetic faults in the io layer**, both invisible to a release build because Lua's `api_check` is debug-only: the `lines()` iterator reserved room for its formats but not the results read on top of them, and the ranged line reader popped the `luaL_Buffer`'s own storage instead of its chunk once the buffer outgrew its inline array — freeing memory still being written through. Both segfault under `--enable-luaext-debug`; both now hold.
- **The call-scope handle sweep could be made to breach the operation quota with no handler in place.** The sweep flushes dirty handles after the protected call has returned, so a script that spent `maxOperations - 1` and abandoned a dirty handle made the sweep's own write the breaching one — an unprotected raise that killed the whole request. The sweep's flush is uncharged now, and `eval()`'s compile-cache bookkeeping moved behind the same trampoline every other host-side push uses.
- **A module that failed to compile poisoned `require()` permanently.** The in-progress mark and nesting depth were set before the loaders ran, and a loader that raised longjmped past the unwind: the module then reported "requires itself", and enough failures left `require()` dead behind an uncatchable depth error. The loader search runs protected now, and the resolver path no longer leaks its `ModuleSource` across a failed compile.
- **`load()` with a reader function could parse forever.** The byte-ceiling wrapper skipped anything that was not a string — while Lua's reader protocol coerces numbers — and was not installed at all with `maxSourceBytes: 0`, leaving the parser's loop with no interrupt observation point. A number-returning reader now bills the coerced bytes, and the wrapper installs unconditionally, carrying the timing check between chunks.
- **A `<close>` handler could smuggle suspended coroutines past the call-scope sweep.** Creating a coroutine mid-sweep inserted into the table the sweep was walking; the rehash skipped entries, and 45 of 50 adversarial calls leaked a resumable coroutine into the next call while `liveCoroutines` read zero. The sweep detaches the table before walking it and refuses coroutine creation for its duration.
- **A conversion charge the budget refused was still discharged.** The accumulator counted bytes before the charge was attempted, so a refused conversion repaid bytes never taken — clamped to whatever was charged, which meant it came out of somebody else's. Measured: one refused conversion took 2,097,249 bytes off a ledger holding a 1 MiB output buffer, leaving every later budget decision to be made against a fiction.
- **Buffered file contents were never charged to `memoryBytes`**, despite the function's own comment and `docs/migrating-from-luasandbox.md` both promising they were. Eight megabytes of file buffers fitted inside a one-megabyte sandbox. They are now charged and refunded against the same ledger as everything else, tracked by what was actually taken rather than by the buffer's length, so a refused charge cannot be refunded twice.
- **A host destructor could close the sandbox out from under the frame that released it.** The deferred queue drained at an outermost return *before* the results were converted and the stack settled, and with `in_lua` already back to zero nothing stopped a `__destruct` from calling `close()` — which `lua_close()`ed the state still in use. Segfaults under `--enable-luaext-debug`. The drain moved after the last use of the state, and the request-shutdown sweep now holds a reference across each close rather than caching a list cursor a destructor can free.
- **`readRange()` was handed a negative length** when `maxFileBytes` was unlimited: "read everything" arrived as `UINT64_MAX` and narrowed to `-1`. Clamped, and a reply larger than the extension can address in one read is refused rather than truncated into a wrong offset.
- **A script could grow the watchdog's process-wide deadline heap without bound.** Every host crossing republished a deadline without removing the one it superseded; superseded entries sit in the heap until their own deadlines pass. Measured over two million crossings: peak RSS 94.5 MB, against 28.4 MB once a republish that would not make the slot fire sooner is skipped — and the armed crossing got cheaper too, 4.55 µs to 3.27 µs.
- **A timing limit too large to express wrapped its deadline.** Past `LUAEXT_LIMIT_MAX_SECONDS` a limit saturates to `UINT64_MAX` nanoseconds; once any of it had been spent, `now + remaining` wrapped to a deadline in the past and the watchdog thread spun servicing it. Measured on a 0.33 s call: 0.60 s of process CPU with 0.22 s of it in the kernel, against 0.33 s total and 0.01 s system once saturated deadlines stay saturated. No `.phpt` can assert this honestly — it needs a wall-clock observation of another thread's CPU — so it is verified by measurement only.
- **The count-hook fallback was chosen before the watchdog thread had ever been started.** The thread starts lazily on the first armed limit, so a sandbox asking "did it fail?" before arming asked a process that had not tried: the answer was no, no fallback was installed, and if the start then failed that sandbox had neither enforcer. The attempt is now made first. Separately, **`setLimits()` did not re-run the `debugHooks`-versus-timing-limit refusal** the constructor applies, so the pair the constructor rejects could be reached through the setter — leaving a sandbox reporting a limit the script can switch off.
- **`VfsQuota::$maxOperations` was never reset.** Documented and implemented as a budget *per sandbox call*, it was in practice per sandbox *lifetime*: the function whose only job is resetting the counter was written, declared, and called from nowhere. A long-lived sandbox eventually refused every filesystem call it was asked for.
- **Three leaks on the paths that only run when something has already gone wrong.** `io.open`, `os.remove` and `os.rename` leaked their canonical path on every quota refusal, and a ranged `file:write()` leaked its whole payload — script-sized, so a loop writing 1 MB chunks leaked a megabyte per refusal. All four are the same cause: `lua_error()` longjmps past the frame's cleanup. Ownership now sits with Lua's collector.
- **`io.lines` read its path after freeing it** — a use-after-free on every "no such file".
- **A CPU breach inside a host callback let the script run further before stopping.** The callback boundary read only the watchdog's flag, so a breach crossed inside a callback — where no interpreter check runs — was delivered only at the next back edge or the end of the call. On an idle machine the script got to run additional work in 80 of 100 near-deadline iterations. The boundary now samples the deadline directly when the callback ran for at least a millisecond; trivial crossings stay at ~0.3 µs (+8%, measured).
- **The unserialize traceback validator accepted two keys no traceback has ever carried.** `lastLineDefined` and `isTailCall` were allowed through on well-typed values despite the capture path never emitting either — and the adversarial test missed it because its shape cases went through the dead mangled key, where the validator never ran. Both tightened, and the test now drives the real key, including pinning the one accept that is by design.
- **A CPU breach close to the end of a call could go unreported.** The watchdog thread sets the interrupt flag when it wakes at the deadline, but the return boundary read only the flag and then disarmed the slot — so a script that crossed its deadline just before returning was back in PHP before the thread's wakeup, which then found nothing to service. On an idle machine 60 of 200 near-deadline breaches returned success; on the shared macOS CI runners the loss was systematic. The boundary now samples the deadline directly, once, before reading the flag, making the verdict independent of thread scheduling.
- **A write refused by the memory budget was reported as an output-limit breach.** The sink returned one `false` for both refusals, so a host whose `memoryBytes` filled while buffering output was told "The sandbox has written all the output it is allowed" — with `outputBytes` barely touched. The refusal now names the budget that actually ran out and raises `MemoryLimitError` for it.
- **`make install` was hidden, and a bare `make` discarded configuration.** The `GNUmakefile` shadow that scopes `clean` also concealed every generated target — `pie install` failed with *no rule to make target 'install'* — and its `build` target re-ran `./configure` over whatever flags a caller had configured with, so CI's sanitizer legs silently compiled against the wrong PHP and every debug leg silently built release. The shadow now forwards unknown targets and only configures a tree that has no Makefile yet, and CI asserts both.
- **`coroutine.resume` answered `message, false`** instead of `false, message` when a coroutine resumed itself: `lua_xmove` is a no-op when its source and destination are the same stack, so the `false` landed on top of the message rather than beneath it.
- **`coroutine.close` accepted a running or normal coroutine**, resetting the stack it was executing on and returning `true`. Upstream refuses both; now so does this.
- **`io.lines` and `file:lines` ignored their format argument.** `f:lines("L")` silently dropped the newline it was specifically asked to keep — no error, just the wrong bytes. Both now route through the same code `:read()` uses, and accept multiple formats and byte counts as Lua does.
- **The PHP 8.5 floor was unenforced at build time.** Declared in `composer.json` and honoured by PIE, but a plain `phpize && make` against 8.4 failed somewhere deep in a translation unit rather than saying so.

### Known gaps

Every capability the extension defines is implemented, and `Sandbox::features()['capabilities']` reports so. What remains:

- The **Windows build compiles and gates**, but runs only `tests/10-lua/` — the
  platform-neutral conformance suite. `tests/02-limits/` asserts far below Windows'
  ~15.6 ms scheduler tick and needs guards written against observed failures rather
  than guessed at.
- The **multi-threaded SAPI paths have no test coverage** — `.phpt` cannot spawn PHP threads.
